# 軽量なプロトタイピング用テンプレート

作りたいものの形が固まっていない間に、**作りながら探る**ための、最小限の雛形です。AI エージェント（Claude Code など）と一緒に進めることを前提にしています。

方向が固まったら、通常のテンプレート（企画書・課金・公開まで）に移ってください。

## 使うとき・使わないとき

| 使う | 使わない |
|---|---|
| 作るものの形が、まだ動く（試して決めたい） | 何を作るか、誰に売るかが決まっていて、公開まで進める |
| 数日〜数週間の試作で、手元で触りたい | 複数人で長く開発する |
| 検証で分かった事実を、あとに残したい | 課金・公開の準備を始める |

## 構成

| ファイル | 役割 |
|---|---|
| [docs/brief.md](docs/brief.md) | 概要1枚。何を作るか、位置づけ、今の理解、いま／次／やらない |
| [docs/decisions.md](docs/decisions.md) | 決めたこと（理由つき）。取り消したら削除する |
| [docs/findings.md](docs/findings.md) | 検証で分かった事実。日付、根拠、未確認の点 |
| [docs/questions.md](docs/questions.md) | 仮説と質問（任意）。成立の基準つき |
| [samples/](samples/) | 実例集。入力と期待値。生データは、個人情報・機密を含まなければ置いてよい |
| [AGENTS.md](AGENTS.md) | AI エージェント向けの軽いルール（探索モード） |

コードの置き場（`src/` や `tests/` など）は、用意していません。技術は、プロジェクトごとに決めてください。

## 進め方

1. **brief.md を書く**（1ページ）。「今の理解」と「まだ分からないこと」を、分けて書く。
2. **作る。**判断が難しいこと（取得方式、通知の条件、安全装置など）だけ、先に短く方針を書いて、人に確認する。画面や文言の細かい調整は、コードとテストで進める。
3. **決めたことは decisions.md に、分かった事実は findings.md に**書く。書くのは、あとで変えにくいものだけ。
4. **引き算を先に考える。**機能を足す前に、外せるもの、1つにまとめられるものはないかを見る。
5. **実機・実データで確かめていないことは、そう書く。**型チェックとテストが通っても、実環境での動作は別。

## 探索から通常の運用へ移る基準

次のうち、いずれかを満たしたら、通常のテンプレートへ移ります（目安）。

- 想定するユーザーへの確認（ヒアリングなど）で、主な仮説が成立した
- 公開・提供の日が決まった
- 複数人で開発する、または課金・認証・個人情報を扱う設計に入る

移るときは、`brief.md` を企画書に、`decisions.md` を意思決定ログに、`findings.md` を検証記録に、それぞれ引き継ぎます。あわせて、`AGENTS.md` の「後方互換は保たない」方針を見直します。
